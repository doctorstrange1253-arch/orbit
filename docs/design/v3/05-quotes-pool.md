## 9. Selection, shortage and presentation rules

1. Select for the actual destination identity from applicable approved records, never from an arbitrary legacy string pool. One immutable attempt snapshots its eligible pool/version; ordinary catalog refresh does not replace text under a focused reader.
2. Choose five or six distinct entries without replacement under the still-unselected count policy. The exact quoted text cannot repeat inside the sequence, even if a future catalog contains duplicate IDs for the same wording.
3. Recent-history avoidance is a soft preference, not rights eligibility. A proposed bounded current-pool/language/identity session history can prefer new entries; if it would leave too few while enough distinct eligible items exist, relax only recency, not source/editorial/rights requirements. Final persistence strategy remains unapproved; no telemetry/account/device-sync promise.
4. Five eligible entries means five. One to four means those items once with disclosed shortage; zero means the static shortage/pending-or-Ready branch from04with no thought counter, fabricated item or silent saved-Fast change.
5. Quote availability does not block core destination readiness or falsely prove it. Skip/Enter, reading holds, visibility holds, precommit Cancel and postcommit recovery follow04. No endless carousel, filler repeat, forced quotation minimum or invented loading percentage.
6. Render exact text and full readable credit as normal DOM/plain text. Identify excerpts/translations/context and expose locator/source details accessibly. Open source links only through explicit user action with safe external-link behavior; do not load third-party source pages to prepare a role.
7. Count actual displayed credit/context for timing; do not truncate attribution to fit04's English5–12word metadata assumption. Larger/localized credit needs revised timing/layout, not altered quote data. No per-quote screen-reader announcements or screen-reader-detection policy.

Source, editorial and rights validation happens before use; a failed quote record is excluded with an explicit authoring/release gap, not replaced by an invented quote. During controlled UI tests, shortage handling can be exercised without claiming the requested full45-item released pool is ready. Final release acceptance must not silently reduce the founder's15-per-identity catalog target.
